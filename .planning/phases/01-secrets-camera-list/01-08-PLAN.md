<objective>
Region auto-detection for login (CAM-02): the app finds the user's gateway among gw-us / gw-eu / gw-sg without manual URL entry, and exposes a `RegionSelector` port that plan 01-09 uses for the device-list region fallback.

Purpose: today the BuildConfig default is the dummy `https://api.yicamalt.local/v1/`, so a new install cannot log in until the user types a gateway URL. The official app has a region selector for the same reason (PITFALLS #1 cause b). Since plan 01-05 the base URL is resolved per request, so switching region is just a config write.
Output: `YiRegion`, `RegionSelector`, real default gateway, bounded login region fallback, tests.
Account safety and request bounds: one press of "login" = at most 3 `GET /v4/users/login` (1 + at most 2 hops), hop only on code `20253`, never on a wrong password or a network error. No background re-login, no loops.
Which region wins when `LOGIN_REGION` and `DATA_REGION` in 01-PROBE-RESULTS.md differ: there is ONE effective base URL. (a) `CROSS_REGION_SESSION: yes` — the build default is `LOGIN_REGION`; the registry (plan 01-09) switches the base URL to `DATA_REGION` once cameras are found there, and that then wins for all later calls; a later login starts on `DATA_REGION` and returns to `LOGIN_REGION` through this fallback (at most 2 extra requests). (b) `CROSS_REGION_SESSION: no` — the login region wins, nothing switches automatically; record the mismatch in the SUMMARY as a gap for the final checkpoint.
Precondition: `.planning/phases/01-secrets-camera-list/01-PROBE-RESULTS.md` has `BRANCH` other than `D`. If it is `D`, do not execute this plan (plan 01-06 halts the phase).
</objective>
