# Phase 6: Релизная сборка и проверка на телефоне - Context

**Gathered:** 2026-11-04
**Status:** Ready for planning

<domain>
## Phase Boundary

Из чистого клона с локальным APK Yi Home собирается подписанный релизный APK (arm64-v8a, armeabi-v7a); вендорские .so извлекаются при сборке и не лежат в репозитории (REL-01). На телефоне пользователя подтверждены все v1-сценарии: список камер, live-view в LAN и удалённо, H.264/H.265, архив SD, лента событий, в том числе при одновременно открытом официальном приложении (REL-02). Финальный прогон `RedactionScanner` по логам реальной сессии без находок; `docs/verification-plan.xml` отражает пройденные гейты.

Вне фазы: новые функции, PTZ, push-уведомления, публикация в магазинах.

</domain>

<decisions>
## Implementation Decisions

### Подпись (REL-01)
- **D-01:** Релизный APK подписывается новым локальным release-ключом, который лежит ВНЕ репозитория (например в папке пользователя). Пароли и путь только в локальных настройках Gradle (не в Git, не в логах, не в документах). В репозитории остаются скрипт создания ключа и инструкция. Один ключ на все обновления поверх без потери входа. Резервную копию ключа делает пользователь (в инструкции указать).

### Сборка (REL-01)
- **D-02:** Сжатие кода R8/minify в релизе ВЫКЛЮЧЕНО, только подпись; нативные библиотеки .so извлекаются при сборке из локального APK Yi Home (как сейчас, проверка sha256 в `app/vendor-natives.sha256`), в Git не попадают. Поддерживаются arm64-v8a и armeabi-v7a. Версия приложения повышается до 1.0.0 (versionCode по возрастанию).

### Проверка «удалённо» (REL-02)
- **D-03:** Удалённый просмотр (LIVE-02, LIVE-07 SD по умолчанию на relay) проверяется раздачей интернета с другого телефона: пользователь включает точку доступа на втором телефоне и подключает к ней Mi 9; камеры остаются в домашней сети, поток идёт не по LAN. Остальные сценарии проводит оркестратор по USB. Если раздача невозможна, фаза закрывается с оговоркой.

### Claude's Discretion

- Имя и расположение release-keystore по умолчанию, формат инструкции, структура проверочного прогона, порядок сценариев, формулировки отчёта.
- Как именно проверить H.265 (если у пользователя нет H.265-камеры, отметить непроверенным в оговорке).
- Проверка «официальное приложение открыто одновременно»: как в Phase 3 (параллельный просмотр).

</decisions>
