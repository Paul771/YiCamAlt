<objective>
Fix SD-01 (H-R9 regression gap) where the SD archive index retrieval fails on TUTK cameras ("YI Home Camera", LIST_FAILED), and resolve the calendar caveat (H-R8/9) so users can pick any past date even if recording dots are absent.

Purpose:
On TUTK cameras, index replies (IOCTRL 793) contain lists of 12-byte index entries. When recordings span many hours or intervals, the response exceeds 1024 bytes. In `TutkCameraLink`, `IOCTRL_BUF_SIZE = 1024` caused buffer overflow (`AV_ER_BUFTOOSMALL`) or payload truncation, causing `SdArchiveCodec.parseTutkIndexPage` to reject the packet and report LIST_FAILED. Increasing the buffer to 8192 bytes solves the issue.
Additionally, in `CalendarGrid` and `ArchiveCoordinator`, date selection was previously restricted only to dates with recording dots or "today". Users could not select yesterday or any earlier date if the index was not yet loaded or if recordings were sparse. Enabling all dates up to today gives users full control to inspect any day.

Output:
Updated `TutkCameraLink.kt`, `SdIndexRepository.kt`, `CalendarGrid.kt`, and `ArchiveCoordinator.kt` with tests.
</objective>
