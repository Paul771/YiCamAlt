# Phase 7 — Инструкция по проверке регрессионных исправлений на устройстве (UAT)

Дата: 2026-11-15.
Устройство: Xiaomi Mi 9 (MIUI, Android 10 / API 29).
Релизная сборка: `app-release.apk` v1.0.1 (versionCode 10001), подписана релизным ключом.

---

## 1. Установка сборки v1.0.1 на телефон

Так как на устройстве уже была установлена релизная сборка 1.0.0, подписанная тем же ключом:
1. Установка через adb (обновление с сохранением данных и входа):
   ```powershell
   adb install -r app/build/outputs/apk/release/app-release.apk
   ```
2. Если MIUI блокирует установку по USB (`INSTALL_FAILED_USER_RESTRICTED`):
   ```powershell
   adb push app/build/outputs/apk/release/app-release.apk /sdcard/Download/app-release.apk
   ```
   После чего открыть проводник на телефоне в папке «Загрузки» и нажать `app-release.apk` для обновления.
3. Проверить версию установленного пакета:
   ```powershell
   adb shell dumpsys package com.yicamalt | Select-String -Pattern "versionName|versionCode"
   ```
   Должно быть: `versionCode=10001`, `versionName=1.0.1`.

## 2. Программа регрессионных проверок

### Проверка 1 (H-R3 / LIVE-06): Звук в Live на TNP-камере «Спальня»
- **Цель:** Убедиться, что mono-звук с камеры TNP выводится в мультимедийный динамик телефона, а не в разговорный earpiece (исправление routing bug MIUI через `USAGE_MEDIA` / `CONTENT_TYPE_MUSIC`).
- **Действие:**
  1. В списке камер выбрать «Спальня».
  2. Дождаться появления живого видеопотока.
  3. Включить звук (тап по иконке микрофона/динамика, чтобы снять mute).
  4. При необходимости увеличить громкость мультимедиа на телефоне.
- **Ожидаемый результат:** Звук из микрофона камеры чётко и громко слышен из внешнего динамика смартфона (не тихий звук из ушного динамика, не тишина).

---

### Проверка 2 (H-R9 / SD-01): Индекс архива SD на TUTK-камере «YI Home Camera»
- **Цель:** Убедиться, что расширение буфера IOCTRL до 8192 байт устраняет ошибку парсинга многостраничного/длинного индекса записей 793.
- **Действие:**
  1. В списке камер выбрать «YI Home Camera».
  2. Под видеопотоком открыть панель SD-архива.
- **Ожидаемый результат:**
  - Индекс записей успешно загружается.
  - Ошибка «Не удалось получить список. Повторить» **не появляется**.
  - На шкале времени отображаются синие/зелёные полосы записей.
  - Начинается воспроизведение архивной записи.

---

### Проверка 3 (H-R10 / EVT-04): Плавность воспроизведения архива при переходе из событий
- **Цель:** Убедиться, что механизм gap recovery в `FrameAssembler` (`GAP_TOLERANCE = 3`) и сброс конвейера декодера (`resetPipeline`) устраняют задержки и слайд-шоу.
- **Действие:**
  1. Перейти на вкладку «События» (Events).
  2. Выбрать любое событие за сегодня или вчера и нажать на него для воспроизведения клипа.
  3. В окне клипа нажать кнопку «Открыть запись на SD».
  4. Наблюдать за воспроизведением видео на экране live/архива.
- **Ожидаемый результат:**
  - Экран переходит в архив к моменту события.
  - Видео воспроизводится **плавно** (полноценный видеопоток, без переключения кадров раз в 3–5 секунд в режиме слайд-шоу).

---

### Проверка 4 (H-R6 / LIVE-07): Качество SD по умолчанию на Relay-соединении
- **Цель:** Убедиться, что при подключении через Relay (удалённый доступ) качество видео по умолчанию выбирается как SD для экономии трафика и стабильности.
- **Действие:**
  1. Подключить телефон к мобильной точке доступа (hotspot) или мобильной сети.
  2. Открыть стрим любой камеры (бейдж `Relay`).
- **Ожидаемый результат:** Бейдж качества сразу устанавливается в `SD`. При желании можно вручную переключить в `HD`.

---

### Проверка 5 (Календарь архива): Выбор любой прошедшей даты
- **Цель:** Убедиться, что календарь позволяет выбрать любой прошедший день (включая вчера/позавчера), даже если на нём нет точки записи.
- **Действие:**
  1. На экране архива нажать на выбор даты (рядом со стрелкой дня).
  2. Нажать на любой прошедший день (например, вчерашний или позавчерашний день без отметки).
- **Ожидаемый результат:**
  - День выбирается без блокировки.
  - Если записей за этот день нет, отображается панель «Нет записей за этот день», но диалог не зависает и не запрещает выбор дня.

---

### Проверка 6 (H-R14): Release logcat sweep
- **Цель:** Убедиться в отсутствии debug-тегов `[BLOCK_` и конфиденциальных данных в релизных логах.
- **Команда выгрузки и анализа логов:**
  ```powershell
  adb logcat -d > scratch/release-1.0.1.log
  ```
- **Ожидаемый результат:** 0 строк с внутренними маркерами `[BLOCK_`, отсутствие паролей, DID и токенов.
