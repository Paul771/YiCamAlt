# Milestone Audit Report: YiCamAlt v1.0

**Milestone Goal:** Открыть приложение → увидеть свои камеры → смотреть живое видео с любой из них, из любой сети, без подписки.  
**Audited:** 2026-11-14  
**Audit Status:** `gaps_found` (все фазы 1–6 реализованы, 27 требований закрыты полностью, 6 требований имеют зафиксированные аппаратные гэпы/оговорки на физическом телефоне).  
**Target Device:** Xiaomi Mi 9 (Android 10, MIUI, API 29), подключён по USB.  
**Release Build:** Версия 1.0.0 (versionCode 10000, arm64-v8a + armeabi-v7a, R8 off per D-02), подписана v2/v3 внешним ключом.

## 1. Executive Summary

Milestone v1.0 достиг основной потребительской ценности:
1. **Камеры и авторизация:** Пользователь входит в свой аккаунт Yi Home, регион серверов определяется автоматически (`gw-us`), список камер кэшируется и отображает статус обеих камер («Спальня» TNP и «YI Home Camera» TUTK).
2. **Живой просмотр (Live View):** Работает на обеих камерах в домашней сети Wi-Fi (LAN) и через мобильный интернет (Relay), со стабильным потоком H.264 на аппаратном декодере Qualcomm Snapdragon 855. Проверено 15+ минут непрерывного LAN-вещания и параллельная работа с официальным приложением Yi Home.
3. **Архив SD-карты:** На камере TNP («Спальня») полностью функционирует: календарь дней с записями, 24-часовая шкала с сегментами, перемотка, пауза/продолжить и возврат к живому видео без разрыва P2P-сессии.
4. **Лента событий:** Загружается из облака (`/v2/alert/list`), кэшируется офлайн в Room, воспроизводит бесплатные 6-секундные MP4-клипы и осуществляет переход к записи на SD-карте к моменту события.
5. **Безопасность и гигиена:** Секреты и вендорские бинарники не попадают в Git (хук pre-commit 13/13 PASS); P2P-пароли хранятся в `EncryptedSharedPreferences`; лог релизной сборки не содержит прикладных debug-вызовов и токенов.

### Статус по требованиям (33 требования v1)
- **27 требований** закрыты полностью (PASS).
- **6 требований** имеют открытые оговорки или аппаратные гэпы (PARTIAL / CAVEATS):
  - `LIVE-03`: H.264 подтверждён; H.265 поддержан в коде и декодере, но не проверен из-за отсутствия камеры с H.265.
  - `LIVE-06`: Звук на TUTK работает («Слышно»); на TNP в live звук не слышен («Не слышно»).
  - `LIVE-07`: Переключение HD/SD работает; при подключении через Relay выставлено HD вместо SD по умолчанию.
  - `SD-01..SD-04`: Архив на TNP работает полностью; на TUTK запрос индекса завершается ошибкой («Не удалось получить список. Повторить»).
  - `EVT-04`: Переход из события в SD-архив работает; воспроизведение архива при переходе из событий идёт как слайд-шоу (кадр раз в 3–5 с).
  - `REL-02`: Регрессия на устройстве выполнена (10 pass, 3 functional gaps, 1 SELinux audit warning).

## 4. Gap Analysis and Tech Debt

По итогам натурных испытаний на реальных камерах пользователя зафиксированы следующие дефекты и оговорки:

### Функциональные гэпы (3 дефекта)
1. **Звук в Live на камере TNP «Спальня» (H-R3, LIVE-06):**
   - *Симптом:* При включении звука в эфире «Спальни» звук отсутствует («Не слышно»). На камере TUTK звук работает.
   - *Вероятная область:* Расшифровка/формат AAC-аудиопотока в `TnpCameraLink` либо аппаратный микрофон/поток конкретной камеры.
2. **Индекс SD-архива на камере TUTK «YI Home Camera» (H-R9, SD-01):**
   - *Симптом:* При открытии архива появляется ошибка «Не удалось получить список. Повторить». Индекс записей по P2P не загружается.
   - *Вероятная область:* Обработка пейджинга IOCTRL 792/793 в `TutkCameraLink` / `SdIndexRepository`.
3. **Плавность воспроизведения SD-архива при переходе из событий (H-R10, EVT-04):**
   - *Симптом:* При переходе к записи на SD через «Открыть запись на SD» из карточки события видео идёт как слайд-шоу (кадр раз в 3–5 секунд), тогда как при прямом открытии архива с экрана камеры видео идёт плавно.
   - *Вероятная область:* Инициализация сессии и буферизация декодера при внешнем вызове `openAt(timeMs)`.

### Косметические и платформенные оговорки (3 оговорки)
1. **LIVE-07 (SD по умолчанию на Relay):** при удалённом подключении через мобильную точку поток стартует в качестве HD, хотя по спецификации на Relay должно выставляться SD.
2. **Календарь SD-архива:** в диалоге выбора даты нельзя выбрать дни, на которых нет точек записей (разрешён выбор только дней с точками и «Сегодня»).
3. **SELinux audit warning в логе релиза (H-R14):** системное предупреждение ядра `avc: denied { ioctl }` на потоке сокетов вендорской библиотеки TUTK (`iotc_sktaskmgr`). Не является ошибкой прикладного кода.
